# `repo` — a personal git repository manager

Status: **design** (pre-implementation). This document captures the design agreed
so far. `link` and `review` are deliberately deferred (see Future work).

## 1. Motivation

A single tool that knows the collection of git repositories on a given machine and
maintains them: which repos exist here, where their upstreams are, where clones
belong, which branches matter, and how each is worked (fork-PR, direct push,
tracked mirror, or vendored). The collection differs per machine (work laptop vs
personal vs constrained jump host), so the tool is driven by a declarative
registry with a per-machine resolution overlay.

The zsh plugin handling and an ad-hoc `wd-repos-update` script are the two existing
special cases this generalises. Success criterion: promoting the zsh plugins into
the registry makes `plugins-update` shrink to a one-line delegation, and
`wd-repos-update` disappears into `repo sync --tag work`, with no lost behaviour.

## 2. Principles

1. **Bootstrap is pure shell; the tool is an enhancement.** Shell startup must
   never hard-depend on the compiled binary. On a box with neither the binary nor
   generated artifacts, the shell reproduces today's behaviour (glob `PRJPATH`,
   `DOTFILES_PLUGIN_SOURCE` plugin cloning). The binary is distributed via a POSIX
   shim (prebuilt download, with `go build` on first run where a toolchain exists);
   **binaries are never committed to the dotfiles repo** (multi-arch, multi-OS).

2. **One-directional shell contract.** `repo` *writes* generated artifacts; the
   shell only *reads* them; startup never invokes `repo`. There is exactly one
   startup code path (read the artifact), exercised on every machine every time, so
   there is no rarely-used fallback that rots. The only pure-shell-that-must-work is
   cold bootstrap, which is tiny and testable.

3. **Declarative desired state, live observed state.** Desired state (which repos,
   upstreams, clone locations, important branches, workflows) lives in a committed
   registry. Observed state (unpushed/unmerged/dirty/divergence) is computed from
   git every run and never persisted. The *only* persisted state is a per-repo
   update timestamp used for cadence.

4. **Never lose work.** Never touch a dirty tree, never force, never move a branch
   with unpushed/unmerged commits without warning. Refuse-and-report beats
   clever-and-sorry.

5. **Per-repo isolation.** Each repo is processed in its own subshell; one failure
   never aborts the sweep; errors are collected and summarised; non-zero exit if any
   failed. (The `wd-repos-update` script's fatal flaw was dying on first failure.)

## 3. Data model

### 3.1 Three layers

1. **Identity registry** — shared, committed to dotfiles. Machine-independent truth:
   logical repos, upstreams, forks, important branches, workflow, hooks, layout.
2. **Resolution overlay** — per-machine, lives where `.zshrc.local` does. Folds
   logical identity → physical remote (the mirror case). Empty on an unconstrained
   machine.
3. **Derived artifacts** — generated by `repo`, read dumbly by the shell. Resolution
   is already baked in, so the shell never sees a mirror rule.

### 3.2 Identity

A repo's definitive identifier is `host:owner/repo` (e.g.
`github:romkatv/powerlevel10k`). The short name (leaf, `powerlevel10k`) is derived
for `cs`/completion. When a short name is ambiguous across repos, only the
`owner/repo` form is offered; a *fork of the same repo* is one entry (the `fork`
field), not a collision.

`host` keys (`github`, `ghe`, `gogsprod`, `gogsdev`, …) are each defined once in a
`[hosts.*]` table, so the same identity resolves to different physical hosts per
machine without changing identity.

### 3.3 Tags carry configuration

Tags are not just selectors; they carry config that repos inherit. Precedence:
`[defaults]` → each `[tag.*]` the repo lists (in order) → the `[[repo]]` itself.

**Tags and workflows are orthogonal.** A tag (e.g. `zsh-plugin`) groups repos and
sets shared defaults and sync scope, but `workflow` is per-repo: some `zsh-plugin`
repos are third-party `mirror`s, others are your own `upstream-push`/`fork-pr` code.

### 3.4 Layout: two orthogonal axes

- **`path`** = `flat` (`~/src/<repo>`) | `owner` (`~/wd/<owner>/<repo>`).
- **`worktrees`** = bool. `false` → the container dir is a single working tree.
  `true` → bare `.git` + one worktree per important branch (+ ad-hoc worktrees).

### 3.5 Workflows

| workflow        | origin / upstream                                  | intent |
|-----------------|----------------------------------------------------|--------|
| `upstream-push` | origin = definitive                                | push branches straight to origin |
| `fork-pr`       | origin = your fork, upstream = definitive          | push to fork, PR to upstream |
| `mirror`        | origin = your safety fork, upstream = definitive   | track upstream but advance only after **review** |
| `vendor`        | origin = definitive (read-only), pinned            | pulled to match a `pin`; never pushed |

`pin` (vendor only): a branch (fast-forward), an explicit tag (checkout), or
`latest-tag` (re-resolve highest semver each run).

### 3.6 Example registry

```toml
# ~/.config/repos/registry.toml   — shared base, committed to dotfiles

[defaults]
home_root = "~/src"
path      = "flat"
worktrees = false
branches  = ["main"]
on_rewrite = "stop"      # stop | follow  (see §5.2)
prune      = "auto"      # auto | report | manual  (see §5.3)

[hosts.github]
base = "git@github.com:"
[hosts.ghe]
base = "git@ghe.example.com:"

[tag.work]
home_root = "~/wd"
path      = "owner"      # ~/wd/<owner>/<repo>
host      = "ghe"
worktrees = true

[tag.zsh-plugin]
home_root = "~/.zsh/plugins"
path      = "flat"

# --- third-party plugin: mirror workflow (review-gated) ---
[[repo]]
id       = "github:romkatv/powerlevel10k"
fork     = "github:michael-odell/powerlevel10k"
tags     = ["zsh-plugin"]
workflow = "mirror"
branches = ["master"]

# --- my own plugin: normal repo I work on ---
[[repo]]
id       = "github:michael-odell/zsh-history"
tags     = ["zsh-plugin"]
workflow = "upstream-push"

# --- work repo: fork-pr, owner-nested worktrees, helm hook ---
[[repo]]
id       = "ghe:cban-ops/pt-helm"
fork     = "ghe:michael-odell/pt-helm"
tags     = ["work"]
workflow = "fork-pr"
branches = ["main", "release"]
hooks    = [ { after = "fetch", run = "helm dep update ." } ]

# --- vendored, pinned to latest tag, read-only ---
[[repo]]
id       = "github:prometheus/prometheus"
tags     = ["vendor"]
workflow = "vendor"
pin      = "latest-tag"
home_root = "~/vendor"
path      = "owner"
```

```toml
# ~/.config/repos/registry.local.toml   — THIS machine only, not shared
# Constrained box: everything reachable only via a private host.
[resolve]
mirror   = "gogsprod:mirrors/"   # physical = base + owner/repo (owner/repo preserved)
apply_to = "*"
[resolve.overrides]
"ghe:cban-ops/pt-helm" = "gogsprod:team/pt-helm"
```

Resolution rule: `overrides[id]` → else `mirror + owner/repo` if matched by
`apply_to` → else `hosts[id.host].base + owner/repo`.

## 4. On-disk layouts

`fork-pr`, `path = owner`, `worktrees = true` — directory named by the **definitive**
identity (not the fork; forks are a remote detail, and naming by identity keeps the
owner-grouping intact):

```
~/wd/cban-ops/pt-helm/
  .bare/          # bare clone. remotes:
                  #   origin   = ghe:michael-odell/pt-helm   (fork — push here)
                  #   upstream = ghe:cban-ops/pt-helm        (definitive — fetch / PR)
  .git            # file: "gitdir: ./.bare"
  main/           # worktree, tracks upstream/main
  release/        # worktree, tracks upstream/release
  fix-thing/      # ad-hoc worktree; pushes to origin (fork)
```

Maintained worktrees (`main`, `release`) track the **definitive** remote so `sync`
keeps them current with the source of truth; work happens on ad-hoc worktrees.
`repo home pt-helm` → `main/` (worktree of `branches[0]`). `worktrees = false`
collapses to a single working tree at the container path.

## 5. `sync` engine

Per repo, in order: **provision** (clone/remotes/worktrees) → **fetch** (all remotes,
prune, tags) → **update important branches** (per workflow) → **run hooks** →
**detect + report drift**.

### 5.1 Per-workflow update

| workflow        | important branch tracks | update action | strayed warnings |
|-----------------|-------------------------|---------------|------------------|
| `upstream-push` | `origin/<branch>`       | fast-forward only | ahead → *N unpushed*; diverged → skip+warn |
| `fork-pr`       | `upstream/<branch>`     | FF to upstream, then push to origin (fork); via `gh repo sync` when available | local commits on important branch → warn; fork push not FF → skip+warn |
| `mirror`        | `upstream/<branch>`     | fetch only; **do not advance**; flag "upstream +N, review pending" | advancing gated on `repo review` |
| `vendor`        | the `pin`               | branch→FF; tag→checkout; `latest-tag`→re-resolve, checkout, report bump | local commits → *"consider changing workflow"* |

Drift detection runs on **all** workflows (vendor included): unpushed, unmerged,
dirty — computed live via `rev-list`.

### 5.2 History rewrites — follow-but-shout

Per repo/tag/branch `on_rewrite`:

- **`stop` (default)** — a non-fast-forward on an important branch, or a moved tag,
  is skipped with a warning. Right default for supply-chain safety.
- **`follow`** — adopt the rewrite (reset branch / retag to the tracked remote)
  without manual intervention, **but always warn that it happened.**

Rails on `follow`: if the branch carries local unpushed/unmerged commits, a rewrite
escalates back to *stop + warn* (never clobber work). The warning fires on
*detection*, so blessed repos still report every rewrite; you just needn't act.
Applies to tags too — a `vendor` pinned tag whose content moves is a rewrite
(default `stop`+warn; a normal *new higher* tag is an ordinary advance, not a
rewrite).

### 5.3 Prune

Per repo/tag/global `prune`:

- **`auto` (default)** — an important branch removed from the registry, or a task
  branch whose upstream was deleted, has its local branch/worktree removed — **only
  if clean and with no unpushed/unmerged commits.** Anything with local work is
  never auto-pruned; it is reported. This reclaims the branches that went nowhere
  and leaves orphaned-work branches standing, increasing their visibility.
- **`report`** / **`manual`** for look-first repos. Explicit `repo prune` always
  available.

New important branch in registry → `sync` adds its worktree.

### 5.4 The `mirror` review gate

Periodic sync always *fetches* (all workflows) and *flags* mirror repos whose
upstream advanced, but does not advance the mirror or the local clone past the last
reviewed point. `repo review <repo>` shows the upstream diff over the current mirror
point and, on approval, pushes to the fork and fast-forwards the local clone.
Trusted workflows (`upstream-push`, `fork-pr`, `vendor`) auto-advance; only `mirror`
waits for your eyes. This is **trigger-independent**: the startup if-due run is not a
weaker mode — it does full writes (including fork pushes; it already holds pull
creds) — but the mirror gate holds regardless of trigger.

### 5.5 Cadence and trigger

Reuses the existing `PLUGIN_UPDATE_FREQUENCY` + `older-than` + timestamp-file
pattern. Global `sync.frequency`, per-tag/per-repo override, `--force` to ignore.
The shell calls `repo sync --if-due` (a cheap timestamp no-op most days; may run
backgrounded after the prompt). After syncing, `repo` regenerates the artifacts so
drift between "registry changed" and "shell sees it" heals on the same beat.

### 5.6 Report format

Config/important branches on the repo's summary line; **task branches with unpushed
commits break out into sub-bullets** so lost work is obvious:

```
repo sync — 12 repos, 3 due
  ✓ powerlevel10k    up to date
  ⏸ pt-helm          main ff +4 · pushed fork · helm dep update ok
      ⚠ fix-login    2 unpushed
      ⚠ spike-auth   1 unpushed, unmerged · 3 weeks stale
  ⚠ charts           main rewritten (a1b→9f3) — stopped (on_rewrite=stop)
  ⏸ prometheus       vendor v2.50.1 → v2.51.0
  ⚑ fast-syntax-hl   upstream +2 — review pending (repo review fast-syntax-hl)
  🗑 idx-old          registry-removed, clean+merged — pruned
  ✗ idx-svc          fetch failed: host unreachable
```

## 6. Emitted artifacts (shell contract)

Live in a machine-local state dir `$REPO_OUT` (default `~/.local/state/repos`);
contents are resolved for this machine and must not be shared. Each carries the
source registry content-hash in a header; a `precmd`/`plugins-update` may compare
mtime/hash and print a one-line "run `repo apply`" hint, but only `repo` ever writes.

**`prjpath.zsh`** — actual working trees (each maintained worktree + each single
clone); replaces the glob at `.zshenv:22`:

```zsh
prjpath=(
  ~/.zsh/plugins/powerlevel10k
  ~/wd/cban-ops/pt-helm/main
  ~/wd/cban-ops/pt-helm/release
  ~/src/charts
  ~/vendor/prometheus/prometheus
)
```

`.zshenv` keeps the tie declaration, sources this, and falls back to the glob when
absent (cold bootstrap).

**`homes.zsh`** — name→home map for `cs`. Unique short names get both the bare and
`owner/repo` keys; ambiguous short names get only `owner/repo`. `@branch` keys
address specific worktrees and double as the branch-completion feed for `_cs`:

```zsh
typeset -gA REPO_HOME
REPO_HOME=(
  powerlevel10k     ~/.zsh/plugins/powerlevel10k
  pt-helm           ~/wd/cban-ops/pt-helm/main
  cban-ops/pt-helm  ~/wd/cban-ops/pt-helm/main
  pt-helm@release   ~/wd/cban-ops/pt-helm/release
  charts            ~/src/charts
)
```

`cs` consults `REPO_HOME` first (registry-correct, worktree-aware) and keeps the
`CDPATH=$PRJPATH` search as the fallback. `_cs` completes `${(k)REPO_HOME}`, giving
`cs pt-<TAB>`, `cs pex/idx-<TAB>`, and branch completion for free.

**`plugins.zsh`** — the `zsh-plugin` subset as `plugin-def <resolved-origin-url>`
lines (origin = your fork for `mirror` plugins, i.e. today's
`DOTFILES_PLUGIN_SOURCE` behaviour, mirror-folded on constrained boxes). `plugin-def`
is untouched; `plugins-update`/`plugins-load` remain the pure-shell floor.

## 7. CLI surface (initial)

- `repo sync [--tag T | <name>] [--if-due] [--force] [-n]` — the engine above.
- `repo status` — drift sweep, no updates (same detection as sync).
- `repo apply` — regenerate artifacts from registry + overlay.
- `repo home <name[@branch]>` / `repo path <name> <rel>` — navigation primitives.
- `repo clone [--tag T]` — initial provisioning from a registry subset.
- `repo prune` — explicit prune sweep.
- `repo list` — enumerate for completion.
- `repo review <name>` — mirror review gate (see §5.4).

## 8. Strangulation / migration order

1. **Plugins first** (smallest, best understood): `plugins-update` →
   `repo sync --tag zsh-plugin` when `repo` present, pure-shell floor otherwise.
   Behaviour upgrades: `mirror` plugins gain the review gate.
2. **Status sweep** → `repo status` (proves discovery + live observed-state).
3. **`wd-repos-update`** → `repo sync --tag work` (proves hooks + fork/upstream
   flows; fixes the die-on-first-failure pain).

Mirror-folding is threaded through from the start (it touches the schema, not a
late add).

## 9. Future work

- **`link`** — `ghlink`++ with database smarts: choose upstream vs fork/clone URL by
  per-repo preference; generalise the existing `ghlink` remote-URL parser.
- **`review`** — full UX of the mirror review gate.
- **Project-as-mode** — a "project" as a tmux-scoped mode like `nook` (active
  worktree + optional env/kube context + `on_enter` handler), possibly merged with
  `nook`. Metadata hangs off logical identity (where `hooks` already live), so the
  schema doesn't foreclose it.
- **Worktree-per-task for agents** — leaning on worktrees instead of numbered clones
  (`charts`, `charts2`, …) for cleaner agent interactions.
- **Cold-bootstrap seed test** — small enough (clone plugins from resolved URLs) to
  test for real in a container, unlike the abandoned full bootstrap test.

## 10. Open decisions

None blocking. Prior open items resolved: fork-pr periodic push (yes — full writes on
if-due run), latest-tag vendor bumps (auto-advance; moved tags still trip
`on_rewrite`), prune default (`auto`, safe-only), rewrite following (`on_rewrite`),
mirror-fold path (preserve `owner/repo`).
